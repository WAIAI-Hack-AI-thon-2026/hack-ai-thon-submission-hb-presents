Meet the Cast

Six characters do all the work. Once you know who they are, the whole system makes sense.

Think of it as a small theatre company

A play isn't one actor on stage — it's a cast, each with one job. Costume, lighting, script, director. You don't need to understand every rope backstage if you know who plays what role.

Our app has six roles. Everything the system does is one of these six characters doing their one thing.

The six actors

🖥️
The Frontend — what the guest sees

Built with React and Vite. Renders the property picker, the review form, the follow-up cards, and the thank-you screen.

🌐
The API — the doorway to the backend

A handful of HTTP endpoints under [api/](api/). The frontend posts data here; JSON comes back.

🧠
The Agent — the decision-maker

Lives in [backend/agent.py](backend/agent.py). Reads the review, looks at the hotel profile, and decides what two questions should be asked.

📏
The Rule Engine — pattern matchers

[backend/rules.py](backend/rules.py) and friends. Use regex to spot topics like bathroom, smell, staff, and billing in the review text.

✨
OpenAI — the ghost writer

A large language model (gpt-4.1-mini) that turns the agent's picks into natural, polite questions with tap-ready options.

📚
The Data Files — the hotel's memory

JSON files in [data/](data/) that remember every hotel's coverage, conflicts, and claimed amenities.

Where each actor lives in the codebase

The folder layout maps one-to-one onto the cast. If you ever need to debug, you already know where to look.

The big idea: separation of concerns

Notice that no single actor "does everything." The Agent doesn't read regex. The Rules don't write sentences. The LLM doesn't touch the data files. Each character does one thing and hands off.

💡
Separation of concerns, in plain English

When each piece has a narrow job, a bug is easier to trace ("which actor is lying?"), a change is easier to make ("just swap the LLM"), and a test is easier to write ("does the Rule Engine detect 'musty'? ignore everything else"). This is one of the oldest and most important patterns in software.

Check your understanding

You want the agent to notice when guests mention "bedbugs" so it can ask a follow-up about pests. Where would you make that change?
