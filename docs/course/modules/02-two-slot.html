The Two-Slot Decision

One fixed question, one situational question. That single rule pins down everything the agent does.

A journalist's two questions

Imagine a reporter interviewing someone about a city council meeting. They have time for exactly two questions. What do they ask?

Question one is obvious: "You mentioned you were frustrated about the zoning vote — can you say more?" You follow up on what the source just said.

Question two depends on context. If a previous source contradicted them, the reporter asks them to settle it. If nobody's mentioned a specific angle yet, the reporter probes that blank spot.

💡
This agent does exactly that

Slot 1 is always the "you just told me X" follow-up. Slot 2 is either conflict resolution (when the hotel has unsettled disagreements) or information gap (when a topic is suspiciously uncovered).

The two slots, visualized

1

Slot 1 — Comment Deep-Dive

Always about this guest's review and ratings. Acknowledge what they said, then dig deeper or broaden. Never robotic.

2a

Slot 2a — Conflict Resolution

If past reviews disagree ("pool was great" vs "pool was closed"), ask the current guest to be the tiebreaker.

2b

Slot 2b — Information Gap

If no conflicts exist, pick a topic the hotel has zero data on (breakfast? accessibility?) and ask about that.

Critical constraint: Slot 2 is either conflict or gap. Never both. Never neither. Conflicts always win when they exist.

The decision tree, end-to-end

1
Read the review text

Run regex over it to detect which topics the guest already mentioned. Those get marked as "already covered."

2
Look up the hotel's conflict list

Does this property have any unresolved "guests disagree" topics? If yes, pick the top one for Slot 2.

3
No conflicts? Compute information gaps

Score every topic by how little this hotel has been reviewed on it. Skip topics the guest already covered.

4
Build one big prompt

Hand Slot 1 context (the review, ratings) and Slot 2 context (either the conflict snippets or the gap list) to the LLM.

5
Get JSON back, render

The LLM returns two questions in a strict JSON schema. The frontend turns them into tap-able cards.
